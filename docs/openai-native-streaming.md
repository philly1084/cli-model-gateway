# OpenAI-compatible native streaming candidate

Release candidate validated with deterministic tests and bounded real-provider canaries. Deployment still requires the signed main-branch image and preservation gates below.

The OpenAI-compatible provider shares its existing request-body builder between buffered and streamed requests, preserving model mapping, reasoning flags, tool policy and continuation/session metadata. Native requests set stream=true and consume SSE incrementally. The separate Kimi Anthropic and image-generation paths retain their existing behavior.

The pull-based decoder supports fragmented UTF-8/CRLF and SSE comments/data framing, validates one choice, tracks model identity, preserves usage, assembles indexed function arguments and complete unindexed Gemini calls, and requires both finish reason and DONE. Tools are emitted only after the entire completed turn and all tool identities/JSON arguments validate. Limits:2MiB transport,256KiB text/reasoning/line,32calls,64KiB arguments,128character identifiers/names. Incomplete, malformed, errored and oversized streams fail without completion or tool release. Partial text remains partial; it is not a successful result.

Chat and Responses endpoints await writable drain and cancel the upstream fetch on client disconnect. Backpressure has a30second fail-closed deadline; provider timeout remains the existing configured value. Cancellation closes this request but cannot undo remote side effects already performed.

Ordinary chat requests can now recover before any output is emitted. Both buffered and native-stream paths classify HTTP 401/403 as auth failure (no same-provider retry, skip auth-blocked siblings), 404 as model_unavailable, and 429/503 as transient (one 150ms retry, then configured fallback). Fallback selection follows the configured model chain, including through blocked siblings to their downstream fallbacks. The stream path can use a buffered fallback when native streaming is unavailable, including the existing Codex/Kimi CLI and Kimi Code provider paths. Retry/fallback shares the execution deadline, attempt budget and allowFallback control; no policy budget is reset. Explicit no-fallback disables recovery retries too.

Recovery applies only to ordinary system/user chat without tools or session/remote metadata. Tool and continuation streams retain their no-replay behavior. Transport failures with uncertain delivery and failures after any emitted content/reasoning/tool event are terminal. Never turn truncated output or a length/tool_calls/error finish reason into a successful stop. SSE errors expose a sanitized terminal code; incomplete/errored streams do not emit DONE. HTTP 200 application/json completions are also accepted upstream and converted to the existing gateway SSE format.

OpenRouter comment/keepalive lines, unknown fields (including provider, reasoning, reasoning_details, native_finish_reason), empty choices and usage-only trailers are ignored or handled as metadata. Only content becomes assistant text; existing DeepSeek reasoning_content and validated tool events retain their contracts. Gemini extra_content is ignored except for the established server-side tool signature handling. Both object and JSON-array upstream error envelopes are decoded. Structured gateway.upstream.failure receipts log upstreamStatus, errorCode and allowlisted upstreamCode, without upstream messages, content, authorization headers or keys.

Tests include deterministic upstream streams, real loopback Chat/Responses first-chunk and disconnect checks, forced downstream backpressure, fragmented tool arguments and correlated continuation, HTTP failure without replay, invalid/truncated/model-changing/oversized streams, and benchmark replay rejection. Cached ARM64 Node20 runtime and dependency tree are used offline under nonroot/read-only/cap-drop/no-new-privileges containers with runc; no software download or installation.

Gemini may return complete unindexed function calls with a stop finish reason. These are normalized only after validating the entire turn. Its opaque tool signature stays in a bounded server-side cache (five-minute TTL, 128 entries, 1 MiB), bound to provider model, exact history, call identity and argument hash. It is never emitted to the client. A changed signed call is rejected; expiration, eviction or process restart can make continuation unavailable and does not trigger an automatic replay. This cache assumes the existing single router replica.

Bounded live canaries confirmed multiple upstream text deltas before completion for Gemini and DeepSeek, a Gemini multiply tool returning 42 followed by a successful continuation, and cancellation after the first text delta. Deterministic tests cover upstream HTTP failures, malformed/truncated streams and no-replay behavior. Live provider availability can still vary.

Release gates: successful CI and signed canonical main image, exact release proof, authenticated attestation verification, preservation dry-run and guarded rollout, then routed provider and Brain acceptance. Real-provider canaries do not certify a deployment. Never use an unsigned local image, alter pins, or bypass release gates.
